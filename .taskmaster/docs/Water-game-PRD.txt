# Tabarka Treasures - Ocean Coral Diving Game

## Overview
Tabarka Treasures is an educational Phaser.js-based ocean game that celebrates Tabarka's rich coral diving tradition. Players control a diving basket/net as they ascend from the ocean depths, collecting traditional coral harvesting treasures while learning about Tabarka's maritime heritage. The game combines engaging gameplay with cultural education about Tunisia's famous coral diving history, traditional fishing practices, and Mediterranean marine life.

**Problem it solves:** Provides an interactive way to learn about Tabarka's unique coral diving culture while offering entertaining gameplay.
**Target audience:** Cultural experience visitors, tourists, and anyone interested in Tunisian maritime heritage.
**Value:** Preserves and shares traditional knowledge while providing an engaging gaming experience.

# Core Features

## 1. Treasure Collection Gameplay
**What it does:** Players control a diving basket/net that moves left and right to catch falling treasures while slowly ascending from ocean depths.
**Why it's important:** Core gameplay loop that's simple, engaging, and accessible to all ages.
**How it works:**
- 5 treasure types: Red coral pieces, traditional diving tools, ancient pottery/amphoras, pearls & shells, historical coins
- All treasures have equal value (keeping it simple initially)
- Items fall at varying speeds and positions from the ocean surface

## 2. Fish Obstacle System
**What it does:** Fish swim horizontally across the screen and remove collected items from the basket when they collide with the player.
**Why it's important:** Adds challenge and strategy - players must balance collecting vs avoiding obstacles.
**How it works:** Fish move in predictable patterns, collision detection removes random items from basket.

## 3. Cultural Education Integration
**What it does:** Displays educational facts about Tabarka's coral diving tradition when players collect treasures.
**Why it's important:** Fulfills the cultural learning objective of the experience.
**How it works:** Short cultural tidbits appear briefly when items are collected (specific facts to be researched and defined).

## 4. Ocean Environment
**What it does:** Immersive underwater setting with coral reefs, marine life, and authentic Mediterranean atmosphere.
**Why it's important:** Creates engaging visual context that reinforces the cultural theme.
**How it works:** Scrolling background with ocean elements, coral formations, and ambient sea life animations.

# User Experience

## User Personas
- **Primary:** Cultural experience visitors and tourists interested in Tabarka's heritage
- **Secondary:** Casual gamers seeking educational entertainment
- **Tertiary:** Older adults (simple controls and clear visuals)

## Key User Flows
1. **Game Start:** User selects difficulty mode (Easy/Medium/Hard) from mode selection screen
2. **Gameplay:** 40-second session of collecting treasures while ascending and avoiding fish
3. **Cultural Learning:** Brief educational facts appear when treasures are collected
4. **Game End:** Score display with potential reward eligibility
5. **Reward System:** Qualifying scores unlock discount coupons (5%/10%/15% based on difficulty)

## Game Mechanics
- **Controls:** Left/Right arrow keys for basket movement
- **Movement:** TBD - instant vs momentum-based movement (to be tested during development)
- **Ascent:** Constant speed that increases with difficulty mode
- **Duration:** Fixed 40-second sessions
- **Scoring:** Points awarded per treasure collected
- **Difficulty Modes:**
  - Easy: Slow ascent, fewer fish, 5% discount reward
  - Medium: Moderate ascent, normal fish frequency, 10% discount reward
  - Hard: Fast ascent, high fish frequency, 15% discount reward

## Integration Requirements
- **Rewards System:** Connect to existing coupon/discount system
- **Badge System:** Award badges for achievements (first play, high scores, etc.)
- **Score Tracking:** Store scores in game_scores table
- **Experience Linking:** Associate with Tabarka experience in experiences table

# Technical Architecture

## System Components
- **Frontend:** Phaser.js 3.90.0 game engine integrated with Next.js React components
- **Game Structure:** Follow existing pattern `/app/games/tabarka-treasures/`
  - `components/` - React wrapper components and UI elements
  - `context/` - Game state management and context providers
  - `hooks/` - Custom hooks for game logic and audio management
  - `assets/` - Game data definitions and asset configurations

## Data Models & Database Integration
- **experiences table:** Link to existing Tabarka experience record
- **game_scores table:** Store player scores and session data
- **rewards table:** Manage discount coupons (5%/10%/15% based on difficulty)
- **user_rewards table:** Track earned coupons per user
- **badges/user_badges tables:** Achievement system integration

## Game Architecture
- **Phaser Game Instance:** Core game loop with scene management
- **Asset Management:** Placeholder shapes initially (cubes, rectangles for treasures/obstacles)
- **Physics System:** Basic collision detection for basket-fish and basket-treasure interactions
- **State Management:** React context for score, difficulty mode, and game progress
- **Audio System:** Deferred until after core gameplay implementation

## APIs and Integrations
- **Supabase Integration:** Existing database connection for scores and rewards
- **Experience Linking:** Associate game with existing Tabarka experience
- **Reward System:** Trigger discount coupon creation based on score thresholds

# Risks and Mitigations

## Technical Challenges
**Risk:** Limited Phaser.js experience could lead to implementation difficulties
**Mitigation:**
- Break development into very small, testable increments
- Test each feature thoroughly before moving to the next
- Start with simplest possible implementations (basic shapes, minimal physics)
- Research Phaser.js documentation and examples for each feature before implementation

**Risk:** Collision detection complexity between multiple object types
**Mitigation:**
- Implement collision detection incrementally (basket-treasure first, then basket-fish)
- Use Phaser's built-in physics system rather than custom collision logic
- Test with simple shapes before adding complex interactions

**Risk:** Performance issues with multiple falling objects and animations
**Mitigation:**
- Start with minimal objects and gradually increase
- Use object pooling for falling treasures and fish
- Monitor performance during development and optimize as needed

## MVP Definition & Scope Management
**Risk:** Feature creep leading to overly complex initial implementation
**Mitigation:**
- Strictly follow the phased approach outlined in roadmap
- Phase 1-3 constitute the true MVP (basic treasure collection with obstacles)
- Database integration and polish are enhancement phases, not MVP requirements

**Risk:** Difficulty balancing game mechanics without extensive playtesting
**Mitigation:**
- Implement configurable parameters (speed, frequency, etc.) for easy adjustment
- Test with placeholder values and iterate based on feedback
- Focus on making the game functional first, balanced second

## Integration & Platform Risks
**Risk:** Database integration complexity with existing reward system
**Mitigation:**
- Study existing game implementations (camel-ride, medina-memory) for patterns
- Test database operations in isolation before integrating with game
- Use existing reward structure as template (points_required, discount_percent)
